# Database Architecture & Schema Reference

Staff Manager uses Supabase (PostgreSQL 15+) with Row Level Security (RLS) on all tables, plus a client-side Dexie (IndexedDB) database for full offline-first functionality.

---

## 1. Migration Order

Migrations are located in `supabase/migrations/`:
- `20261008000000_initial_schema.sql` (Migration 001) - Baseline tables, triggers, and RPCs.
- `20261009000000_phase1_hardening.sql` (Migration 002) - Security hardening, compensation isolation, invite checks, owner protection, same-business foreign integrity.

## 2. Table Specifications

### Core System Tables

| Table | Primary Key | Description |
|---|---|---|
| `public.profiles` | `id` (references `auth.users`) | User metadata, name, phone, language preferences. |
| `public.organizations` | `id` (UUID) | Business entity with owner, currency, country, week start, and JSONB settings. |
| `public.memberships` | `id` (UUID) | User role in organization (`owner`, `manager`, `supervisor`, `accountant`, `viewer`). Protected by last-owner trigger. |
| `public.invites` | `id` (UUID) | 12-char invite codes with expiration and max uses. Role restrictions enforced via RLS. |
| `public.devices` | `id` (UUID) | Registered user devices for session and sync audit tracking. |
| `public.audit_log` | `id` (bigint identity) | Immutable audit log generated by DB triggers recording before/after JSON snapshots. |

### Synced Business Tables
All synced tables contain standard sync metadata columns: `id`, `org_id`, `created_at`, `updated_at`, `created_by`, `updated_by`, `device_id`, `revision`, and `deleted_at`.

| Table | Description | Access Rules |
|---|---|---|
| `public.sites` | Sites / Projects / Locations. | Read: all roles. Write: owner, manager. Delete: owner. |
| `public.work_types` | Task types / Piece-work definitions. | Read: all roles. Write: owner, manager. Delete: owner. |
| `public.custom_field_defs` | Dynamic custom fields per entity. | Read: all roles. Write: owner, manager. Delete: owner. |
| `public.staff` | Core staff profile (name, code, phone, status, `payment_type`, `unit_name`, `hours_per_day`, `weekly_off`). **No pay rates stored here.** | Read: all roles. Write: owner, manager. Delete: owner. |
| `public.staff_compensation` | **Sensitive financial pay data** (`rate`, `overtime_rate`, `rate_history`, `payment_note`). Unique on `(org_id, staff_id)`. | Read: `can_view_money(org_id)` (owner, manager, accountant, viewer if allowed). **Supervisors barred.** Write: owner, manager. Delete: owner. |
| `public.attendance_entries` | Daily attendance records (`present`, `absent`, `half`, `leave_paid`, `leave_unpaid`, `holiday`, `overtime_hours`). Unique on `(org_id, staff_id, work_date)`. | Read: all roles. Write: owner, manager, supervisor. Delete: owner. |
| `public.work_entries` | Daily tasks, quantities, and hours per worker. | Read: all roles. Write: owner, manager, supervisor. Delete: owner. |
| `public.payments` | Salaries, advances, deductions, bonuses, reimbursements. | Read: `can_view_money(org_id)`. Write: owner, manager, accountant. Delete: owner. |
| `public.period_closings` | Monthly closing locks preventing edits inside closed ranges. | Read: `can_view_money(org_id)`. Write: owner, manager, accountant. Delete: owner. |

## 3. Database Triggers & Integrity Guards

1. **Audit & Revision Triggers (`set_audit_fields`, `log_audit`)**:
   - Automatically maintains `revision`, `created_at`, `updated_at`, `created_by`, and `updated_by`.
   - Records all row mutations (insert, update, soft delete, purge) into `public.audit_log`.

2. **Last Owner Protection (`protect_last_owner`)**:
   - `BEFORE UPDATE OR DELETE ON public.memberships`
   - Blocks removing, demoting, or suspending the last active owner of an organization.
   - Allows cascade deletion when the parent organization itself is deleted.

3. **Same-Business Cross-Entity Checks**:
   - `BEFORE INSERT OR UPDATE ON public.attendance_entries`, `work_entries`, `payments`, `staff_compensation`
   - Validates that `staff_id`, `site_id`, and `work_type_id` all belong to `new.org_id`.

4. **Invite Role Restriction (RLS)**:
   - Managers may only invite `supervisor`, `accountant`, or `viewer`.
   - Only Owners can create or edit invites for the `manager` role.

---

## 4. Privileged Functions (Security Definer RPCs)

- `create_organization(p_name, p_business_type, p_currency, p_country)`: Atomically provisions organization and assigns caller as active `owner`.
- `accept_invite(p_code)`: Atomically validates code, expiration, and use limits, then creates active membership.
- `delete_my_account()`: Deletes user account and sole-owned organizations, ensuring residual records in `public.audit_log` are completely purged. Refuses if organizations retain other active members.
